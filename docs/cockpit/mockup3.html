1 — THE BUTTON PROBLEM IS IN AANG, NOT JUST THE MOCKUP

Theme.cs sets ButtonPx = 8f and draws labels in Press Start 2P. That is a decorative face doing a reading job. Stardew and Ocarina of Time do not do this — their buttons use a chunky readable face, and the pixel font is kept for plaques and small labels. Press both rows.

BEFORE — 8px pixel font
AFTER — 14px bold, hard shadow
2 — THE MODE CHIPS WERE HOLLOW

Outlined with a pale fill reads as empty and the text had nothing to sit on. Each mode already has its own colour in Theme.cs — Quick cyan, Smart blue, Deep purple — so fill the chip with it, put dark readable text on top, and give it the same lip as a button so it is obviously pressable.

WHAT THIS MEANS FOR THE REAL APP

The button fix is a change to Theme.cs, not just to the cockpit. Press Start 2P should be reserved for plaques, eyebrows and tiny labels; anything you need to READ wants Atkinson bold with a hard shadow. That one change would make the bubble easier to use today, before any of Phase 6 exists.

Everything else here — the scale, carved headings, rules with an ornament, the highlighter, the carved underline, tabular numbers — is impossible in the bubble as it stands, because GDI draws plain strings. That is the Phase 6 argument in one paragraph.
